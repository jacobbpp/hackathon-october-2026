Getting set up

Get the repo, then get your tools running. Power BI and Excel need no setup. The starters are there if you want them; you don't have to use any of them.

  1. 1

    Get the repo

    Clone it, or download it as a zip if git is new to you.

    git clone https://github.com/jacobbpp/hackathon-october-2026.git
  2. 2

    Power BI or Excel

    Nothing to set up. In Power BI choose Get data, then Text/CSV; in Excel, Data, then From Text/CSV. Pick files from data/, or data/clean/ once your team has cleaned them.

  3. 3

    Python notebook starter (Python 3.10 or newer)

    pip install -r notebook/requirements.txt
python notebook/check_setup.py
  4. 4

    Plain web starter: HTML, CSS and JavaScript

    Nothing to install beyond Python or VS Code. Browsers won't load data into a page you double-click, so serve the repo folder, then open http://localhost:8000/web/. (Use python3 on a Mac.) Or use VS Code's Live Server extension on web/index.html.

    python -m http.server 8000
  5. 5

    React + Node starter (Node 20 or newer)

    For teams who already know React.

    cd react
npm install
npm run check
npm run install:all

The checks tell you what, if anything, to fix. If something won't install, grab a coach, and pair with a teammate while it's sorted.

Two jobs, one team

Make the data trustworthy

Find what's wrong with it, fix it in a way you can repeat, and find out what it really says.

Build LoopBike Ops

A tool Priya's team would actually use, running on the cleaned data. Build it in Power BI, Excel, Python or code.

Most teams are mainly data analysts, so expect most tools to be built in Power BI, Excel or Python. Where a team has a developer, they and an analyst lead the build together.

The two jobs meet in a data contract: the names and columns of the cleaned files, agreed by the first checkpoint. The people cleaning produce files that match it; the people building the tool build against it, using a few hand-written sample rows until the real files are ready. Nobody waits for anybody.

What Priya's team has asked for

Build in priority order: a few stories that work well beat many that half work.

Must

  • Every station listed once, with its real departures and arrivals
  • Stations likely to be empty by 09:00 on a weekday, for the van driver
  • Pick a station and see its busiest hours, weekdays and weekends

Should

  • Members whose riding has dropped off, before they cancel
  • Filter by date range and rider type

Could

  • A map of stations, coloured by how often they run empty
  • Tomorrow's expected departures for each station (Tier 3)

Quality bar: someone outside your team can open it and use it from your instructions; a non-technical person can use it unaided; blank or odd values don't break it; and re-running the cleaning, then refreshing the tool, brings it up to date.

Build it in what your team knows. Power BI, Excel, Python (such as Streamlit) and code are all equally good routes. You're judged on whether it works for the user, not on the technology.

Challenge tiers

Every tier has somewhere easy to start and no ceiling. You don't need to finish one tier before a teammate starts the next.

1

Clean and explain

Data side

Cleaning you can re-run from scratch, and a log of every decision. Going further: find what a quick look misses.

Build side

Agree the data contract, get the tool reading the cleaned files, and get the first Must story working.

2

Explore and build

Data side

Answer the three questions with evidence. Going further: an insight that needs two files joined.

Build side

All three Must stories working on cleaned data. Going further: the Should and Could stories.

3

Predict (optional)

Data side

Beat the notebook's baseline, and say honestly how wrong your model is.

Build side

Tomorrow's expected departures in the tool, with how sure the prediction is.

Rules of the day

AI assistants are allowed

If you can't explain it, it doesn't count. Judges may ask any team member about any part of your work.

Every decision about the data goes in the log

Dropping rows, filling gaps, merging values: write it in DATA_QUALITY_LOG.md with your reason.

Keep your cleaning repeatable

A script or notebook you can run again from scratch, not edits by hand.

Agree the data contract early

By the first checkpoint, in DATA_CONTRACT.md. Change it only together.

Build in priority order

Musts first. A few stories that work well beat many that half work.

Ask the coaches

They won't build it for you, but they will help you get unstuck.

Showcase and judging

5 + 3

Five minutes to demo and three minutes of questions per team. Cover the problem, what you built, what you found and what you'd do next.

Judges look for

  1. A clear definition of the problem
  2. Sensible use of data
  3. The quality and clarity of the solution
  4. Evidence of effective teamwork
  5. How well the team explains its approach

Awards

  • Best Overall Solution
  • Best Data Insight
  • Best Technical Build
  • Audience Favourite

Best Technical Build is for the best-made thing in any tool: code, Power BI, Excel, or a repeatable, tested cleaning pipeline.

Each member of the overall winning team receives a £50 Amazon voucher.

A focused, well-explained Tier 1 and Tier 2 beats a half-finished Tier 3.
